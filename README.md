# 🫧또또SFW

### v0.2.22 — 일반 갱신에도 인포블럭 날짜·시각 우선

새 답변의 상태 태그를 저장할 때, 같은 원문의 `<Info_panel>`에 `[Date: ...]` 또는 `[날짜: ...]`가 있으면 그 값을 시간 항목에 우선 저장합니다. 날짜·요일·시각을 그대로 유지하며 ‘늦은 오후’ 같은 태그 설명으로 덮어쓰지 않습니다. 패널에 날짜 값이 없으면 기존 상태 태그의 시간 설명을 사용합니다. 표시용 번역(`extra.display_text`)은 읽지 않습니다.

추가 API 호출이나 보조 AI 활성화는 필요하지 않습니다. 업데이트 이후 새로 수신한 상태 태그부터 적용되며, 과거 저장 기록을 일괄 변경하지 않습니다. quiet 주입 유지와 NSFW 연동은 유지합니다.

### v0.2.21 — quiet 전환 시 기존 주입 유지

quiet 시작 이벤트와 인터셉터에서 기존 주입문을 삭제하거나 교체하지 않습니다. 일반 생성 시작 때 등록한 지시가 quiet 단계에서도 유지됩니다. 이전 버전의 ‘숨은 RP 생성 호환’ 토글과 조건부 프롬프트를 제거했으며 별도 설정은 필요하지 않습니다. 기존에 주입문이 없다면 quiet에서 새로 만들지는 않습니다.

진단에 ‘quiet · 기존 주입 유지 (삭제·교체 없음)’을 기록합니다. 특정 확장과 연결하지 않으며 자동 보정 설정과 API 호출 수는 바꾸지 않습니다. 일반 생성의 상태 변경, 채팅 변경, 사용 해제, NSFW 인계 등에 필요한 초기화는 유지합니다. 유지된 지시는 같은 채팅 문맥을 사용하는 요약 등 다른 quiet 호출에도 포함될 수 있습니다. 태그 출력과 실제 환경의 갱신 성공은 별도 확인이 필요합니다.

### v0.2.19 — 독립 동작 정리

다른 확장이 일반 생성을 먼저 중단하여 또또의 인터셉터까지 도달하지 못하는 경우에 대비해, 실제 GENERATION_STARTED 이벤트에서도 상태 지시를 등록합니다. dryRun에서는 주입을 변경하지 않습니다. 정상 인터셉터 경로에서는 같은 주입 키를 다시 갱신하므로 지시문을 중복 추가하지 않습니다.

특정 외부 확장의 설정 조회, 프롬프트 판별 및 숨은 RP 전용 허용 경로를 제거했습니다. 또또SFW의 일반 생성 시작 주입과 진단 기능은 유지합니다. quiet·impersonate에는 상태 지시를 넣지 않습니다. 진단의 quietToLoud 값만 남기며 보조 생성 프롬프트 본문은 읽거나 기록하지 않습니다.

자동 보정 설정과 API 호출 수는 바꾸지 않습니다. 모델이 상태 태그를 생략하거나 다른 확장이 최종 전송 전에 제거하는 경우까지 보장하는 수정은 아닙니다.

### v0.2.17 — 일반 생성 유형 호환 수정

SillyTavern 1.12.14의 일반 전송은 Generate(undefined)를 사용합니다. 이를 미지원 유형으로 거르던 문제를 수정했습니다. undefined/null/빈 문자열은 일반 생성(normal)으로 처리하고, regenerate/swipe/continue도 유지합니다. quiet·impersonate에는 RP 상태 지시를 넣지 않으며 기존 상태 주입을 제거합니다. 그 밖의 알 수 없는 유형은 주입을 추가하거나 변경하지 않습니다.

진단에 생성 시작 및 인터셉터 유형을 기록합니다. undefined와 명시적인 normal을 구별하며 임의 객체·문자열은 내용 대신 자료형만 남깁니다. 자동 보정 설정과 API 사용 방식은 변경하지 않았습니다. 이 변경은 일반 생성 호환성 수정이며, 모델의 상태 태그 출력 자체를 강제하거나 보장하지는 않습니다.

### v0.2.16 — 갱신 진단 기록

장면 상태 탭의 ‘갱신 진단 기록’에서 주입 등록·생략, 메시지 이벤트, 상태 태그 누락/미완성/JSON 오류, 메시지 메모리 반영, 채팅 저장 요청, 보조 분석 결과를 확인하고 복사할 수 있습니다. 채팅별 최근 80개를 메타데이터에 보관하며 본문·인물명·키·오류 원문은 기록하지 않습니다. 추가 API 호출이나 자동 보정 설정 변경은 없습니다.

업데이트·새로고침 후 새 답변을 하나 받고 생성이 끝난 뒤 ‘진단 복사’를 사용하세요. 과거에 제거된 태그나 이전 버전의 주입은 복구하지 못합니다. 주입 등록은 setExtensionPrompt 호출 확인이며 실제 API 전송 프롬프트 포함을 보증하지 않습니다. 진단은 관찰용이며 기존 태그 처리 동작을 바꾸지 않습니다. ‘기록 비우기’는 진단만 비우며 채팅 본문과 장면 상태는 유지합니다.

### v0.2.15 — 분석 중복 취소·재시도 누락 수정

같은 답변의 수신·렌더·관찰 이벤트가 겹쳐도 진행 중인 분석을 취소하지 않습니다. 실제 원문이나 선택한 스와이프가 바뀌면 기존 결과를 폐기하고 최신 답변 분석을 이어갑니다. 취소 신호를 무시하는 API도 확장 내부 대기열을 막지 않으며 늦게 도착한 결과는 저장하지 않습니다. 베르바의 표시용 번역(`extra.display_text`)은 원문 변경으로 취급하지 않습니다.

동일 답변의 자동 보정 실패를 렌더 이벤트마다 무한 재시도하지 않습니다. 연결 오류 등을 해결한 뒤에는 ‘상태 다시 분석’으로 재시도할 수 있습니다. 기존 ‘태그 누락·불완전 시 자동 보정’ 설정은 유지됩니다. 이 옵션이 꺼져 있고 상태 태그도 없다면 별도 AI 보정은 실행하지 않습니다.

### v0.2.14 — 분석 응답 형식 오류 수정

보조 AI 응답과 `<sfw_scene>` JSON의 문자열 안에 실제 줄바꿈·탭이 들어가 생기는 `Bad control character` 오류를 로컬에서 보정합니다. 보정에 추가 API 호출은 없으며, 값은 보존합니다. 잘린 JSON이나 그 밖의 구조 오류는 임의로 채우지 않고 저장 실패를 알립니다.

전연령 롤플레이용 장면 연속성·서사 흐름 관리 확장입니다. 기존 🌀또또가 반복되는 문장과 표현을 관리한다면, 또또SFW는 장소·시간·인물·사물 상태와 일반 장면의 행동·대화 흐름을 관리합니다.

또또NSFW와 저장 키, 상태 태그, 설정 화면, 주입 키가 분리되어 있어 함께 설치할 수 있습니다. 둘 다 설치한 경우 또또SFW는 단어를 별도로 재판정하지 않고 또또NSFW의 실제 개입 상태를 따릅니다. 또또NSFW가 대기 중이면 또또SFW가 계속 동작하고, 또또NSFW가 무장한 동안과 해제 브릿지 한 턴에만 자동으로 대기합니다.

## 주요 기능

### 장면 상태 추적

AI 응답 끝의 `<sfw_scene>{...}</sfw_scene>` 태그를 읽어 다음 상태를 기록합니다. 태그는 화면에 보이는 본문에서 제거됩니다.

- 장소
- 시간·시간대
- 환경 상태
- 중요 사물의 위치·상태
- 인물별 외형·복장, 자세·위치, 소지품, 신체 상태
- 장면 유형과 진행 단계

### 장면 유형별 진행 관리

현재 장면을 다음 유형 중 하나로 자동 분류합니다.

- 일반
- 일상
- 대화
- 로맨스
- 갈등
- 액션
- 조사·미스터리

슬로우번을 사용할 때 각 유형에 맞는 6단계 진행표가 적용됩니다. 예를 들어 액션은 위협 확인부터 결정적 행동과 후속 장면까지, 대화는 주제 형성부터 핵심 질문·응답·결정까지 별도로 관리합니다.

### 최근 전개 반복 방지

최근 AI 답변에서 이미 일어난 주요 행동·감정·서사 전개를 기록하고, 말만 바꾼 비슷한 전개가 반복되는 것을 막습니다. 문장 표현 반복을 관리하는 기존 🌀또또와는 별개입니다.

### 대사 전개 반복 방지

같은 질문·부탁·칭찬·경고·도발·사과처럼 대사의 목적이 말만 바뀌어 반복되는 것을 막습니다. 범위는 최근 1~6개의 AI 답변으로 조절할 수 있습니다.

### 대화 흐름 추적

현재 대화 주제, 답변을 기다리는 직전 질문, 이번 AI 답변에서 새로 밝혀진 사실만 기록합니다. 사용자가 이미 답했거나 주제를 바꿨다면 이전 질문을 억지로 되풀이하지 않도록 지시합니다.

일반적인 미해결 약속·목표·단서·갈등 목록은 만들지 않습니다.

### 장면 전환 연속성

설명 없이 장소가 바뀌거나 시간이 건너뛰고, 진행 중인 대화가 갑자기 끝나는 현상을 줄입니다. 본문에 이동이나 시간 경과가 자연스럽게 묘사된 경우에는 정상적인 장면 전환을 허용합니다.

### NSFW 장면 자동 인계

최근 대화에서 성적 장면 신호를 로컬로 감지하면 또또SFW의 프롬프트 주입, 슬로우번, 태그 누락 자동 보정을 잠시 멈춥니다. 또또NSFW가 함께 설치되어 실제 개입 중이면 그 상태를 우선 확인합니다.

장면 신호가 3개 메시지 연속으로 사라지고 또또NSFW의 해제 브릿지까지 끝나면 또또SFW가 자동으로 복귀합니다. 건너뛴 구간 이전의 상태는 재사용하지 않고, 복귀 후 첫 AI 답변에서 현재 SFW 상태를 새로 기록합니다. 이 감지는 브라우저 내부에서 처리되므로 별도의 API 호출이 발생하지 않습니다.

### 다음 전개 힌트

AI가 제안한 다음 전개 후보 중 최근 전개·새로 확인된 사실·사용자 금지·하드 리밋과 겹치지 않는 것만 다음 생성에 힌트로 넣습니다. AI는 현재 대화 주제, 아직 답을 기다리는 질문, 새로 확인된 사실을 함께 고려해 가장 자연스러운 후보를 선택하거나 더 알맞은 전개로 이어갑니다.

### 슬로우번

선택한 강도에 따라 각 진행 단계에서 최소 1~3개의 AI 답변을 유지합니다. 같은 행동을 복사하는 것이 아니라 같은 단계 안에서 새로운 대사·반응·세부 행동을 쌓습니다.

### 태그 누락 자동 보정

상태 태그가 누락되거나 필수 항목이 비어 있으면 최근 대화를 보조 AI로 다시 분석해 상태를 복구합니다. 별도 호출 비용이 발생할 수 있으며 전용 연결 프로필을 지정할 수 있습니다.

## 기능 프리셋

- **연속성만:** 상태 추적과 갑작스러운 장면 전환만 관리
- **기본:** 연속성 + 최근 전개·대사 반복 방지
- **서사 관리:** 기본 + 대화 흐름 + 다음 전개 힌트
- **슬로우번:** 서사 관리 + 장면 유형별 단계 제한
- **사용자 설정:** 개별 기능을 직접 조합

프리셋을 고른 뒤 개별 기능을 변경하면 자동으로 사용자 설정으로 전환됩니다.

## CardInject 연동

CardInject에서 분석한 캐릭터 시트 카테고리 중 선택한 내용을 다음 전개 힌트의 참고 자료로 사용할 수 있습니다. 개입 중이며 다음 전개 힌트가 켜져 있을 때만 적용됩니다.

## 사용법

1. 확장을 설치하고 실리태번을 새로고침합니다.
2. `현재 채팅에서 사용`은 기본으로 켜져 있습니다. 필요하면 채팅별로 끌 수 있으며 마지막 선택이 저장됩니다.
3. 기능 프리셋을 선택합니다. 기본 추천은 `서사 관리`입니다.
4. 실제 다음 생성에 들어갈 내용은 장면 상태 탭의 `주입문 보기`에서 확인합니다.

또또SFW는 잔잔한 일상 장면에서도 연속성을 관리하므로 `현재 채팅에서 사용`을 켠 동안 계속 동작합니다. 또또NSFW가 함께 설치되어 있으면 그 확장의 실제 무장 상태만 따르며, 또또NSFW가 대기 중일 때는 SFW가 계속 동작합니다. 단독 설치에서는 최근 두 메시지의 현재 성적 행동이 분명할 때만 잠시 대기합니다.

NSFW에서 SFW로 돌아올 때는 최신 또또NSFW 상태표의 장소·복장·자세·접촉·최근 행동을 SFW 상태로 즉시 넘겨받습니다. 넘겨받을 상태표가 없고 자동 보정이 켜져 있으면 최근 대화를 보조 AI로 분석해 복귀 상태를 채웁니다.

메시지 수신·생성 종료·렌더 완료·번역 등으로 인한 메시지 편집 뒤에 최신 응답을 다시 확인하며, 이벤트가 누락되어도 최신 메시지와 스와이프의 변경을 가볍게 감시합니다. 보조 분석 중 새 답변이 들어오면 오래된 결과를 폐기하고 최신 답변을 다시 분석해 시간·장소·행동·다음 장면 추천을 과거 상태로 덮어쓰지 않습니다.

보조 분석 결과를 저장할 때는 최신 응답의 `<Info_panel>`에 적힌 날짜·시간·날씨·장소를 다시 대조하며, 이 명시값이 보조 AI의 추론보다 우선합니다.

각 상태표에는 원본 메시지·현재 스와이프의 지문을 함께 저장합니다. 유저 메시지가 마지막에 있더라도 가장 가까운 최신 AI 답변을 찾으며, 과거 버그로 잘못 붙은 상태표나 내용이 다른 스와이프의 상태표는 분석 완료로 인정하지 않고 다시 갱신합니다.

## 한계

- 프롬프트 주입 방식이므로 모델의 지시 이행 능력에 따라 효과가 다릅니다.
- 상태 태그를 모델이 반복해서 누락하면 보조 AI 호출이 늘어날 수 있습니다.
- 상태 항목을 많이 추적할수록 주입문 길이가 늘어납니다.
